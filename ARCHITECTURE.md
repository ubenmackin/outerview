# OuterView — Architecture Blueprint

Architectural blueprint for **OuterView**: a Safari-faithful web browser built for dual-screen and foldable form factors (specifically the iPhone Duo), claiming the entire 466 × 678 pt outer display edge-to-edge with scroll-transient chrome and contextual command controls.

---

## 1. Soul & Design Theses

Stock Duo web content pins Safari to a narrow 382 pt strip beside a static side rail. OuterView claims the entire outer display edge-to-edge and replicates Safari's tactile feel while making chrome transient: controls disappear when reading starts.

1. **Chrome is Transient**: Chrome steps aside for content. The side rail hides after 8 pt of accumulated downward scroll; finger-down alone only resets the gesture accumulators and never hides visible chrome. The address pill minifies after 24 pt of accumulated downward scroll and restores on a 32 pt upward scroll. On regular width landscape the toolbar plus tab strip collapse exactly when the address pill minifies (24 pt) — one synchronized step, never the 8 pt rail step — and restore with it. Standard non-Duo iPhones run Mode 3 (`nonDuoPhone`): the outer-style bottom pill flanked by `Back` leading and `Tabs` trailing bottom stacks with `topBarView` hidden in browsing (`topContentInset = max(0, safeAreaTop)` parking web content below the status cluster); Settings, Downloads, and BookmarkEditor surface the same `RailMode` composition in a transparent `TopBarView` (`showsBackgroundBar == false`) instead of a side rail. Mode 4 (`duoInnerOrPadPortrait`) drops the top bar and horizontal tab strip, running bottom-anchored controls flanked by `Back`/`Bookmarks` leading and `New Tab`/`Tabs` trailing stacks with an edge-anchored `VerticalTabBarView` for thumb-driven tab switching.
2. **Pill-Tap Restore Plus Interactive Pill Pans**: No floating restore button remains. When the rail is hidden, tapping the address pill restores rail plus expanded pill and never opens the editor. Pill swipes are finger-tracking interactive pans on Safari directions, active in Mode 1, Mode 3, and Mode 4 (Mode 2 landscape disables pill swipes): swipe-up shrinks the live view in place into a tab card with 1:1 finger tracking, anchoring the touch point under the finger, and commits into the selected tab's frame in the collection at 30 percent of view height or on an upward 800 pt/s flick, with pop-back below; horizontal pans traverse tabs within the active scope with the outgoing snapshot following the finger, committing at 40 percent of content width or on a same-direction 800 pt/s flick, with bounce-back otherwise. Left means next, right means previous; overflow past the last tab creates one Start Page tab in the same scope. No haptic plays on any pill path.
3. **Wall-to-Wall Content**: WKWebView fills the window edge-to-edge; liquid glass chrome floats above it and adjusts content insets dynamically.
4. **Contextual Command Rail**: The 84 pt right system column is an adaptive command rail driven by `RailMode` (`.browsing`, `.startPage`, `.library`, `.bookmarkEditor`, `.settings`, `.downloads`). Contextual actions (Cancel, Save, Edit, Clear, Done) are surfaced directly in the rail rather than crammed into top navigation headers. On regular width the identical `RailMode` composition renders into the top toolbar and the rail hides; in Mode 3 (`nonDuoPhone`) the rail also hides and the browsing composition renders into bottom flanking stacks (`Back` leading, `Tabs` trailing) with `topBarView` hidden, while Settings, Downloads, and the non-modal BookmarkEditor render the same composition into a transparent `TopBarView` (`showsBackgroundBar == false`) — shown whenever the non-modal editor is visible, including with the library open — and Library plus Overview keep `topBarView` hidden. Tab overview bypasses `RailMode` and composes its own rail via `TabOverviewViewController.applyRailItems(to:)`.
5. **Unified Start Page**: A single `StartPageView` serves empty tabs, menu-triggered home access, and the address bar editing backdrop. Large high-res site favicons, recent visits, and Safari import actions live in this single surface.
6. **Dual-Placement Chrome**: Compact width (outer display) uses the bottom pill plus right rail. Regular width landscape (inner display landscape, iPhone 17 Pro Max landscape) uses a top toolbar with the centered pill, a live tab strip, and no rail; regular width portrait (Mode 4) uses the bottom pill plus edge-anchored vertical tab bar with no top bar. One `ChromePlacement` value resolved from `BrowserInterfaceMode` (`.duoInnerOrPadLandscape` → `.regular`, otherwise `.compact`) drives the swap; unfolding is a trait change with no state loss. Non-Duo phones resolve placement `.compact` but render bottom flanking stacks instead of the rail via `BrowserInterfaceMode == .nonDuoPhone` (`topBarView` hidden in browsing with `topContentInset = max(0, safeAreaTop)` parking web content below the status cluster; transparent `TopBarView` only for Settings, Downloads, and BookmarkEditor).
7. **Swift 6 Concurrency**: Built from day one with strict concurrency, `@MainActor` UI isolation, and immutable `Sendable` value types.
8. **Reuse over Reinvention (P1)**: New features extend the shipped architecture rather than adding parallel subsystems. Reader mode and Find in Page transform the SAME `WKWebView` document; the chrome FSM is untouched by P1 overlays.
9. **Safari-Parity Background Downloads (Phase 2)**: Standard downloads run through a background `URLSession` in the `nsurlsessiond` daemon and survive suspend plus terminate, waking the app to finalize into `Documents/Downloads`. Private tabs stay foreground-only via in-process `WKDownload`. Downloads declare no entitlement and use no `UIBackgroundModes` of their own (CloudKit sync separately declares `remote-notification`, see §4.8).

## 2. Technology Stack & Runtime Environment

- **Language & Platform**: Swift 6 language mode, iOS 27.1 deployment target.
- **Project Generation**: Declarative `project.yml` managed via **XcodeGen**. The generated `.xcodeproj` is never manually modified or committed; run `xcodegen generate` whenever files are added or removed.
- **UI Architecture**: UIKit-first browser surface utilizing custom `UIViewController` containment for granular animation and gesture control. SwiftUI is integrated via `UIHostingController` for structured modal sheets (`BookmarkEditorView`, `SettingsView`, `DownloadsSheetView`).
- **Web Rendering**: WebKit (`WKWebView`) with customized navigation policies, process pooling, and certificate challenge handling (`SFSafariViewController` is excluded because its chrome is rigid and non-transient). WebKit's native interactive back/forward edge swipes are enabled once in `WebPageController.init`. Release builds stay non-inspectable (`isInspectable` gated to `#if DEBUG`); private-tab DOM stays unreachable to attached inspectors.
- **Persistence**: **SwiftData** backed by a shared `ModelContainer` managing `Bookmark`, `BookmarkFolder`, `HistoryEntry`, `TabRecord`, `TabGroup`, `TabSession`, `RecentSearch`, and `ReadingListItem`. An in-memory configuration is supported for unit test isolation. The on-disk container syncs through a CloudKit private database (`iCloud.com.volcrypt.OuterView`, entitlements in `Support/OuterView.entitlements`) with fail-closed local fallback; `TabSession` carries a CloudKit-safe `tabIdsEncoded` order string alongside its legacy `tabIds` array. Lightweight settings mirror through `NSUbiquitousKeyValueStore` (`SyncedSettingsStore`); per-host website settings for private tabs stay in session memory only, and per-site text zoom for private tabs applies to the live view only. Tiny host-keyed preferences (per-site text zoom) use `UserDefaults` instead of a model.
- **Visual Design System**: Liquid Glass styling with blurred materials, capsule geometry, and subtle borders (`GlassEffect.swift`, `UIVisualEffectView`). `GlassEffect.make()` vends `UIGlassEffect(.regular)` with `isInteractive` on iOS 26 plus later and `UIBlurEffect(.systemMaterial)` below. All browsing chrome visuals plus elasticity come from system `UIToolbar` plus `UIBarButtonItem` plus `UIButton.Configuration.glass`; custom `RailButton` circles, `tertiarySystemFill` styling, and per-button `UIVisualEffectGlass` glass stay rejected.
- **Data Import**: Safari-exported `Bookmarks.html` (Netscape bookmark format) imported via standard Document Picker without requiring private APIs or sandbox violations.

## 3. Display Geometry & Spatial Allocation

| Display Target | Dimensions (pt) | Scale | Safe Area Insets | Key Physical Characteristics |
| :--- | :--- | :--- | :--- | :--- |
| **Outer Portrait** | 466 × 678 | @3x (radius 59) | top: 0, left: 0, right: 84, bottom: 34 | Right 84 pt column hosts system status & camera spot; bottom 34 pt home indicator |
| **Inner Landscape** | 951 × 669 | @3x | top: 0, left: 0, right: 84, bottom: 34 | Expanded widescreen canvas; right column reserved for controls |
| **Inner Portrait** | 669 × 951 | @3x | top: 0, left: 0, right: 84, bottom: 34 | Regular width portrait; bottom floating pill & flanking buttons with thumb-zone vertical tab bar |

### Safe Area Strategy
- **Right System Column (84 pt)**: Hosts the system status cluster (time, cellular, battery) and camera occlusion (an ~84 × 174 pt region containing the camera hardware). OuterView centers its 44 pt interactive command rail (`SideRailView`) at 47 pt from the trailing display edge to align button centers directly under the Control Center icon, positioning buttons below the camera region. The column carries system status only on compact; on regular width the vertical bar is disabled via `preferredVerticalBarBehavior` and status moves to the top axis. The preference crosses the SwiftUI bridge through a host view controller deferring to the browser root.
- **Bottom Bar Spacing (34 pt)**: In browsing mode, the address capsule floats 4 pt above the bottom safe area (`38 pt` total offset from screen bottom). In address editing mode, the field docks cleanly above the active `keyboardLayoutGuide`.
- **Dynamic Transition Handling**: When migrating between displays, transition frames are handled through `viewWillTransition(to:with:)` and `layoutSubviews`. Size classes transition between compact-width/regular-height (outer) and regular/regular (inner). Folded landscape (compact/compact) keeps compact chrome with no new work.

### Interface-Mode Classification Carve-Out
- **`BrowserInterfaceMode` resolution** (`BrowserRootViewController.swift`; cases `duoOuter`, `duoInnerOrPadLandscape`, `duoInnerOrPadPortrait`, `nonDuoPhone`) distinguishes the four display targets. Sole decider is `BrowserRootViewController.interfaceMode(horizontalSizeClass:safeAreaInsets:bounds:deviceName:)` (`isPortraitRegular(bounds:)` with `portraitRegularWidthThreshold` 500): launch args (`-OuterViewInnerLandscape`, `-OuterViewInnerPortrait`, `-OuterViewInnerDisplay`, `-OuterViewNonDuoPhone`, `-OuterViewDuoOuter`) first, then regular horizontal size class → portrait when `bounds.height > bounds.width && bounds.width >= portraitRegularWidthThreshold` else landscape, then Duo outer geometry (right safe area ≥ 44 pt or window bounds within 1 pt of 466 pt) or a `SIMULATOR_DEVICE_NAME` containing "Duo" (simulator fallback) → fail-closed `nonDuoPhone`. Mode 3 and Mode 4 share `applyBottomChromeVisibility(isPortrait:isOverlay:hideBottomButtons:hideLeading:hideTrailing:)` for bottom-stack fade plus hide plus pill-hidden plus pill anchors; top, rail, strip, and vertical-bar visibility stay in the per-mode callers.

### 4.1 Chrome & Contextual Rail
- **Status bar contract**: `BrowserRootViewController.shouldHideStatusBar(for:mode:)` hides the system status bar only in Modes 1, 2, and 4 while `state.pill == .minified` (false while editing, overview visible, or a sheet overlay is visible); Mode 3 never hides it. `BrowserChromeHostViewController.childForStatusBarHidden` forwards the query to the browser root, and the root fades updates via `preferredStatusBarUpdateAnimation = .fade` with parent-forwarded `setNeedsStatusBarAppearanceUpdate()`. On regular width this complements the TopBarView collapse, which fades the status cluster from the top axis.
- **`SideRailView`**: Native Liquid Glass buttons (`UIButton.Configuration.glass`) aligned under the hardware Control Center icon at 47 pt from the trailing display edge. Single rendering owner is `SystemToolbarMapper` (`Sources/Browser/Chrome/SystemToolbarMapper.swift`) mapping each `RailAction` (systemImageName, accessibilityLabel, isProminent, isEnabled, menu/menuProvider, showsMenuAsPrimaryAction, handler) into native glass buttons via `populateStack(_:with:axis:)` with full remove plus rebuild on every change. Disabled Back stays visible at 0.35 alpha with UIKit dimming; hit target 44, symbols 17–22. Context-driven via `RailMode`:
  - `.browsing`: Back button (dynamically enabled based on web view history), Bookmarks library trigger, New Tab, and Tab Overview.
  - `.startPage`: Prominent Blue Checkmark (`Done`) button.
  - `.library(tab)`: Done button at bottom; contextual actions at top (Add Folder and Edit for Bookmarks; Clear for History; Reading List surfaces display, filter, and select actions through an ellipsis menu). Reading List selection mode repurposes the prominent blue check to mean "done selecting" (it exits selection mode and restores the normal Reading List rail) and keeps batch deletion as the trash action at the TOP of the rail; the blue check resumes its exit-the-Library role once selection mode ends.
  - `.bookmarkEditor`: Cancel (`xmark`) at top; Save (`checkmark`) at bottom.
  - `.settings`: Blue-check Done dismissing the embedded full-screen Settings sheet.
  - `.downloads`: Files opener and confirmation-gated Clear All (`promptClearAllDownloads`) on top; blue-check Done dismissing the Downloads sheet.
  - Tab overview bypasses `RailMode`: `TabOverviewViewController.applyRailItems(to:)` puts Search and an ellipsis menu (Manage Tab Groups, New Group…, Close All Tabs behind a confirm sheet) on top, New Tab and Done at the bottom, all rendered as system toolbar glass via `SystemToolbarMapper` with tap plus hold elasticity.
  - No floating restore button exists. When collapsed the stacks fade out with no replacement affordance; pill-tap restores.
  - On regular width the rail hides and the same composition renders into `TopBarView`; in Mode 3 (`nonDuoPhone`) the rail also hides and the browsing composition renders into bottom flanking stacks — `Back` leading and `Tabs` trailing at 16 pt horizontal insets, owned by `makeBrowsingChromeItems` (`prefix: [backAction]`, `suffix: [tabAction]`; other modes keep Back + Bookmarks leading and New Tab + Tabs trailing) — with `topBarView` hidden (`isHidden == true`, `topContentInset = max(0, safeAreaTop)` parking web content below the status cluster). Only Settings, Downloads, and BookmarkEditor show a transparent `TopBarView` (`showsBackgroundBar == false`) — the editor's bar appears whenever its non-modal presentation is visible, including with the library open, surfacing Cancel/Save through the `.bookmarkEditor` rail composition and the `performBookmarkEditorCancel`/`performBookmarkEditorSave` seams; Library and Overview keep `topBarView` hidden.
- **`TopBarView`**: Regular-width toolbar spanning the physical width edge to edge under the status cluster (`84 pt` expanded, collapsing to `48 pt` remnant on scroll, Mode 3 height 44 pt), rendered with shared toolbar glass so page content flows cleanly behind it. Single rendering owner is `SystemToolbarMapper`: `TopBarView.setItems(prefix:suffix:)` delegates to `populateStack(_:with:axis:)` for `leadingStack`/`trailingStack` with native Liquid Glass buttons (`UIButton.Configuration.glass`), consuming the identical `RailAction` prefix and suffix arrays as the rail so compact and regular never diverge in available commands. Leading inset `28 pt` with `12 pt` stack spacing plus pill gaps; trailing clearance `84 pt` (expanding dynamically for top-trailing status occlusions) so buttons clear both curved corners and park alongside the clock + Control Center cluster. Expanded pill caps at `380 pt` centered on the bar; collapsed hides the button stacks, fades out the status bar, and keeps a domain-hugging mini capsule centered. Collapsed top inset equals the `48 pt` remnant so sticky page headers park below the remnant with content flowing behind. Mode 3 reuses this view with `isNonDuoPhone` (`mode3BarHeight` 44 pt, `nonDuoHorizontalInset` 16 pt, collapsed height 0): browsing keeps `topBarView` hidden with `topContentInset = max(0, safeAreaTop)` parking web content below the status cluster so the collapsed-height step never shows; the bar appears only for Settings, Downloads, and BookmarkEditor with `showsBackgroundBar == false` (transparent, no blur) — for the editor, whenever the non-modal editor is visible even with the library open — and stays hidden for Library and Overview.
- **`TabStripView`**: Regular-width live tab strip beneath the toolbar showing the active mode tabs with favicon, title, and close affordance in Mode 2 (`duoInnerOrPadLandscape`). Visible with two or more tabs; hidden otherwise. Tap switches through `selectTab`, close removes through `closeTab`; long-press drag reorders via `canMoveItemAt`/`moveItemAt` plus `reorderTabs`/`spliceTabOrder`/`saveSession` persistence shared with the overview collection; the strip never shows the inactive mode. Tab titles and icons update in real time on snapshot commit (`handleSnapshot(_:for:)`).
- **`VerticalTabBarView`**: Portrait regular-width vertical live tab bar (52 pt width, 40×40 pt button items, 20 pt favicons) floating along the display edge within thumb reach in Mode 4 (`duoInnerOrPadPortrait`). Position defaults to the right edge with user preference for left edge persisted in `UserDefaults` (`portraitTabBarPosition`, synced via KVS). Rendered in Liquid Glass, fades out in unison with the minified pill and bottom chrome — never on the 8 pt rail step; `shouldHidePortraitChrome` covers overlay, library, minified pill, and single tab only.
- **Sheet presentation**: On Mode 1 (`duoOuter`), Library, Settings, and Downloads are overlay containers pinned to the root view edges with command buttons driven by `RailMode` in the contextual side rail. On Mode 2 (`duoInnerOrPadLandscape`), Mode 4 (`duoInnerOrPadPortrait`), and Mode 3 (`nonDuoPhone`), Settings and Downloads present natively as modal `.pageSheet` sheets (`presentSettingsSheet`/`dismissSettingsSheet`, `presentDownloadsSheet`/`dismissDownloadsSheet`, `presentationController.delegate = self`), with per-sheet toolbar composition (Downloads: folder + trash in `.topBarLeading`, Done in `.confirmationAction`); dismissal — programmatic or system swipe — restores chrome via `updateRailItems`/`applyRailViews`/`bringChromeToFront`. On regular width, modal presentations (Library, Settings, Downloads) keep `TopBarView`'s browsing buttons and `TabStripView` visible behind UIKit's native dimming scrim, retaining normal browsing actions instead of adopting modal sheet actions. `BookmarksLibraryView` trailing commands render on one shared-glass `UIToolbar` via `SystemToolbarMapper.makeItems(_:)` with live reload resetting items on the same instance. On compact, command buttons stay rail commands composed by `RailMode`; on regular the rail stays hidden. Mode 3 and Mode 4 take the regular grouped header for the library overlay (`chromePlacement == .regular || isNonDuoPhone`, where `isNonDuoPhone` is true for `nonDuoPhone` and `duoInnerOrPadPortrait`, `.systemGroupedBackground` with inline toolbar commands) so the 48 pt compact-header constant stays dead; in Mode 1 the full-screen library covers the floating pill (z-order scoped to Mode 3 retained chrome), while in Mode 3 the bottom address bar is retained per §5.2.
- **`OverlayCardView`**: Placement-driven scaffold owning heavy-blur dim, centered max-width card with content padding, corner radius, and content pinning used as fallback overlay presentation on compact containers.
- **`AddressBarView`**: Liquid glass floating capsule displaying security status (lock icon), page domain/title, reload/stop action, and page menu anchor. Morphs between expanded (44 pt height) and minified (30 pt height). Shows a download progress ring in the action slot while downloads run and the page is idle; tapping the ring opens Downloads. While Find in Page is active, the find capsule (`FindInPageView`) occupies the pill's exact frame — the FSM is not involved; the overlay is independent like `errorContainer`. SOLE owner of pill gestures: one axis-locking pan (horizontal tab traversal plus vertical overview drag, tap requires the pan to fail) with nonisolated pure commit math (0.40 width or same-direction 800 pt/s fling horizontal, 0.30 height or upward 800 pt/s flick vertical) plus pure card math (0.30 scale rate, radius 24) with 1:1 anchor math via `overviewDragOffset` committing into `selectedCardFrame`; pan events carry only the locked-axis value and root handlers own the transitions. The page-menu button owns a single presentation path: with a provider set the system UIMenu owns the tap and the touchUpInside forwarder is uninstalled; without a provider the forwarder presents the fallback sheet. Two simultaneous presentations on one layer log bounds/position decomposition warnings.
- **`AddressEditorView`**: Full-bleed editing overlay docked above `keyboardLayoutGuide` on compact. Its `bottomBarContainer` extends 16 pt from the view's leading and trailing edges, filling into the rail column so the address capsule and inline dismiss button span across the display without a gap. On regular it floats as a centered translucent blurred popover card (`600 pt` max width, `28 pt` corner radius, `.systemChromeMaterial`) directly over the address bar slot while leaving the live `WKWebView` and `TopBarView` browsing controls untouched underneath; displays Favorites tiles when focused/idle and switches to live suggestions when typing, dismissing on outside tap or Escape. Features an integrated `UITextField` with `clearButtonMode = .whileEditing` and a suggestions `UITableView` with `automaticDimension` row height. Suggestions render in `SuggestionSection` groups (an engine-predictions section plus a Bookmarks/History/Tabs section; UI-layer grouping only — the §4.2 engine pipeline is unchanged). Touches inside the capsule forward to `capsuleView.hitTest` so the in-field clear button receives taps; `textFieldShouldClear` (`AddressEditorView+Delegates`) clears the text and restores the Recent Searches view.
- **`ChromeStateController`**: Pure, deterministic finite state machine driving chrome transitions from scroll offsets, drag events, and editing lifecycle changes. Thresholds (8, 24, 32) are shared across placements; on regular placement the root collapses the toolbar plus strip synchronously with the pill's 24 pt minification rather than the 8 pt rail step. P1 introduces no new FSM inputs or states.

### 4.2 Address Editing & Suggestions Pipeline
- **`SuggestionEngine`**: High-performance multi-source candidate ranking pipeline:
  1. **Open Tabs**: Immediate matching against existing tabs (`SuggestionKind.openTab`), enabling one-tap switching.
  2. **Remote Suggestions**: Live per-engine completions (Google, Bing, DuckDuckGo; Brave has no stable keyless endpoint and gets local candidates only), supporting both OpenSearch array and phrase shapes.
  3. **Bookmarks & Favorites**: Host and title matches from `BookmarkStore`.
  4. **History & Recent Searches**: Recent search terms when the input is empty; chronological history visits when typing.
  5. **Web Search**: Fallback search query for the selected default search engine.
  6. **Find on Page**: In-page text search trigger when an active web page is loaded.
- **Execution Strategy**: Local candidate ranking (tabs, bookmarks, history) runs **synchronously on the main thread (< 1 ms latency)** for instantaneous keystroke response. Network queries to remote suggest endpoints run in the background with a 120 ms debounce.
- **`FaviconService`**: Asynchronous favicon fetching and disk caching with monogram generation fallback for instant visual recognition.

### 4.3 Web Surface & Tab Management
- **`WebPageController`**: Wraps `WKWebView`, manages navigation delegates, script injection, progress observation, pull-to-refresh, certificate verification, and snapshot caching. Standard downloadable responses cancel WebKit and forward to `BackgroundDownloadService` with cookies plus user agent; private tabs return `.download` for in-process `WKDownload`. WebKit error 102 surfaces as a silent handover, never an error page. Navigation titles track via `currentDocumentTitle`, reset to nil in `didStartProvisionalNavigation` and replaced only by the new document's title, so a stale previous-page title never bleeds into the next history record. Snapshot capture (`takeSnapshot()`) passes a `WKSnapshotConfiguration.rect` starting at `adjustedContentInset.top` so header and tab-strip inset areas do not produce blank top rectangles in tab card snapshots. WebKit's native interactive back/forward edge swipes are enabled exactly once, in `WebPageController.init` (`webView.allowsBackForwardNavigationGestures = true`), the single funnel through which `TabPool` creates and recreates every live web view — this is the Safari-exact engine for left-edge back and right-edge forward; no other file sets or toggles the flag. P1 adds: `WKUIDelegate` element context menus (links/images via `ElementContextMenu`), the download policy (downloadable navigation actions and responses route per privacy; `DownloadsManager` owns rows for both paths), find-in-page JS engine (`findText`/`findStep`/`clearFind`), reader-mode DOM transforms (`toggleReader`/`setReaderTheme`/`setReaderFontSize`, guarded by a document generation so stale extractions never touch a new document), and per-site `pageZoom` application (`SiteZoomStore`).
- **`TabPool`**: Manages the lifecycle of live tab controllers. Enforces a 30-tab live memory cap using an LRU eviction policy (evicting inactive WKWebViews to disk snapshots while preserving tab state and navigation history).
- **`TabOverviewViewController`**: Visual card grid (cols = `max(2, floor(width / 180))` on compact, `max(2, floor(width / 260))` on regular) featuring snapshot previews, close buttons, real-time title search filtering, and **tab groups**. On Mode 2 (`duoInnerOrPadLandscape`), overview actions render directly in `TopBarView`'s leading and trailing header stacks alongside the status cluster with the browser address pill hidden, `inlineBar` suppressed, and tab cards sized with a landscape aspect ratio (`TabCardCell.landscapeAspectHeightOverWidth = 0.75`). In Mode 3 (`nonDuoPhone`) and Mode 4 (`duoInnerOrPadPortrait`), shows a system-glass inline toolbar (`inlineBar` 44 pt via `SystemToolbarMapper.makeOverviewToolbarItems(prefix:suffix:)`) with search, options menu, New Tab, and Done (`showsInlineCommands == true`); Mode 1 keeps rail composition unchanged. Card context menu `makeCardContextMenu`: Copy Link + Move to Group + Close Other Tabs + Close Tab; zero-member groups hidden. Bottom chrome is ONE Safari-style glass capsule owned by **`TabGroupPickerBar`** (`Sources/Browser/TabOverview/TabGroupPickerBar.swift`): a segmented row — `Private`, `<N> Tabs`, and one named segment per non-empty tab group — with a `slidingPillView` marking the active selection; the capsule's accessibility value remains "<other mode> · <N> Tabs" via the shared `compactSegments`/`compactTitle` builder. Tapping the active segment opens the **`TabGroupsSheetController`** sheet (medium detent, grabber); tapping an inactive segment instead slides the pill over and applies that selection; a horizontal scrub slides the pill between segments with selection haptics, applies each hovered selection live, and commits on release. Mode/group application lives in **`TabOverviewViewController+Picker.swift`** (`updatePickerBar`, `applyPickerSelection`, `applySelectionBatched`, `showGroupsSheet` sheet presentation). Group membership math lives in `TabOverviewViewController.members(tabs:of:)` (a nil group selects everything); membership writes go through `TabStore.assignTab` plus `deleteGroup`, which orphans deleted-group members to ungrouped.
- **Group delegate protocol**: `TabOverviewViewControllerDelegate.tabOverview(_:didCreateGroup:withTabIDs:)` is the single own-side batch creation method. The owner (`BrowserRootViewController+Overview.swift`) creates the group and assigns every listed standard tab (empty array = empty group). Private tabs are never assigned.
- **TabCardCell**: Card with preview + favicon/title/host strip, a visible 28 pt close button at the preview's top-left, and horizontal-only immediate swipe (`isImmediateSwipe<0.30s`, `abs(vx)>abs(vy)*1.2`): the swipe drives a `cardContainer` transform with `cancelsTouchesInView=true` and `simultaneous=false`, dismissing via `shouldDismissSwipe`/`shouldBeginSwipe` thresholds.
- **ElementContextMenu**: Pure UIMenu builder — the canonical item owner. Links: Open in New Tab, Add to Reading List, Copy Link, Share. Images: Open in New Tab, Save to Photos, Copy Image, Share. Photos saving declares `NSPhotoLibraryAddUsageDescription`.
- **Edge navigation gestures**: Left-edge back/forward is WebKit native (see `WebPageController` above). The left-edge **child-tab close** — a link-opened tab with no back history closing back to its parent — is a custom `UIScreenEdgePanGestureRecognizer` (`.left` on `contentContainer`) owned solely by `BrowserRootViewController+EdgeSwipe.swift` (`installEdgeCloseGesture`, pure `EdgeClosePolicy`, `EdgeCloseSession`): the page slides right following the finger while the parent tab slides in from the left underneath, committing via `AddressBarView.shouldCommitHorizontal(translationX:width:velocityX:direction: .right)` and `settleDuration`, closing through `closeTab` with the parent pre-selected, and restoring the child on cancel. The gate is fail-closed (see §5.7); `TabRecord.parentTabID` (§4.6) supplies the lineage.

### 4.4 Library, Bookmarks, Favorites, History & Reading List
- **`BookmarksLibraryView`**: Full-screen overlay for Bookmarks, Favorites, History, and Reading List library on compact; hosted inside `LibrarySheetViewController` (`.pageSheet`) on regular with a Safari-style two-row header (section title + `36 × 36 pt` circular `•••` options menu and `✕` close buttons on row 1, full-width `LibraryTabBar` on row 2, `.systemGroupedBackground` surface, and zero raw `.system` blue text buttons). In Mode 3 (`nonDuoPhone`) and Mode 4 (`duoInnerOrPadPortrait`, via `isNonDuoPhone`) the view takes the regular grouped-header path (same two-row header with `.systemGroupedBackground` and inline commands) with the ✕ close suppressed — dismiss is owned solely by the bottom bar's `xmark` "Dismiss"; header button counts are Start Page 0, Bookmarks/History/Reading List 1 (`...` menu only, shown only with a non-empty menu mirroring the rail-path guard); the compact header constraints stay inactive and `topBarView` stays hidden. `LibraryTabBar` segment 0 swaps the Start-page grid icon ⇄ magnifier instantly (`UIView.performWithoutAnimation`) to reflect the search sub-mode; tapping segment 0 returns to the Start Page. Tapping the Mode 3 pill opens the library at `.startPage` with the bottom address bar retained (bottom leading stack hidden, pill expanded to the leading edge); the bottom trailing action is always `xmark` labeled "Dismiss". Selecting any suggestion, bookmark, history, or reading-list row — or pressing Return — calls `closeBookmarksLibrary()` and loads immediately; `dismissStartPageOrEditing()` exits editing and closes the library whenever `isLibraryVisible`.
- **`RecentSearchesView`**: Persistent recent-query list shown over the Start Page content while editing the address bar inside the library. Backed solely by the existing `RecentSearchStore` (injected, no parallel persistence): "Recent Searches" header with a Clear All action, per-row select-arrow plus delete affordances, Dynamic-Type-scaled title.
- **Library search tuck contract**: In all three searchable lists the search bar is **hidden by default** and revealed only by pulling down from the top. `LibrarySearchTuckController` (Sources/Browser/Bookmarks/LibrarySearchHeaderView.swift) is the SOLE tuck decider: every host list re-asserts the hidden state via `reassert` immediately after every `tableReload` (`reassert` detaches the header via `requiresCollapse` on short lists that cannot tuck, otherwise re-attaches the header and tucks via `enforceTuck`); first-layout tuck stays in `layoutTuckIfNeeded`; re-exposure on reload is a bug. The spacing between the revealed search bar and list content is owned by the header view's internal padding (`defaultHeight` 64 with ~14 pt bottom padding), never by per-list constants.
- **`BookmarksBrowserView`**: Hierarchical bookmark navigator supporting nested folders, section-bound drag-and-drop reordering, and context-menu operations.
- **`BookmarkEditorView` + `BookmarkEditorModel`**: Dedicated bookmark editing surface for modifying title, URL, and destination folder using `BookmarkLocationTree`. Directly integrated with side-rail Cancel/Save buttons on compact and inline toolbar items on regular. In Mode 3 the non-modal editor surfaces Cancel/Save through the transparent `TopBarView` (shown whenever the editor is visible, including with library-open) via the `.bookmarkEditor` rail composition. In Mode 4 the editor keeps `topBarView` hidden and surfaces Cancel/Save through the bottom stacks (portrait `setChromeItems` clears `topBarView` items in every branch via `setItems(prefix: [], suffix: [])` while `topBarView` stays hidden per `applyPortraitChromeVisibility`), with the overlay covering overview, editing, and find while library and bookmark editor route through dedicated branches.
- **`FavoritesGridView` + `FavoriteTileCell`**: Safari-faithful grid displaying large custom-rendered favicon tiles with rounded corners. Press-drag reorders tiles through the collection drag and drop delegates with persistence through `BookmarkStore.reorderBookmarks`; drops commit with batch delete plus insert and never reload inside the drop. The Start page grid (`StartPageView` collection with `dragInteractionEnabled`) reuses the pure reorder helpers (`FavoritesGridView.canBeginDrag`/`reorderedIDs`) with the same persistence, keeping press-drag reorder reachable in production.
- **`HistoryListView` + `HistorySegmenter`**: Chronologically partitioned browsing history (Today Morning / Afternoon / Evening, Yesterday Morning / Afternoon / Evening, Previous 7 Days, Older) with swipe-to-delete and full clearance.
- **`ReadingListView`**: Saved-pages list mirroring the History list pattern (insetGrouped rows, favicon, semibold unread titles, swipe-to-delete, display/filter/select through the rail ellipsis menu with batch deletion in selection mode). Opening a row marks it read so Unread Only filters work. P1 loads saved pages as ordinary URLs; no offline snapshot cache.

### 4.5 Reader Mode & Per-Site Zoom
- **`ReaderMode`** (pure engine): extraction script (idempotent, `window.__outerviewReader` namespace; ≥ 60-char paragraph heuristic; not readerable when text < 200 chars), `replaceBodyScript` applying light/sepia/dark themes and 14–28 pt font (default 20) inline on the live document, restore via `webView.reload()`. Preferences persist in `UserDefaults` keys `readerTheme` / `readerFontSize` (mirrored to KVS for iCloud sync). Reader state clears on every navigation/reload.
- **`SiteZoomStore`**: `UserDefaults` dictionary (key `siteZoom`, mirrored to KVS for iCloud sync) mapping host → zoom, clamped 0.5–3.0 in 0.1 steps (entry removed at 1.0). Applied to `WKWebView.pageZoom` on every navigation commit; zoom controls (In/Out/Reset) live in the page menu; Settings offers "Reset All Text Zooms". Private tabs apply zoom to the live view only (`WebPageController.setTextZoom` / `currentTextZoom` guards); private hosts never reach persisted defaults.

### 4.6 Data Persistence & Storage
- **`OuterViewDatabase`**: Central SwiftData `@ModelContainer` wrapper providing thread-safe main-actor model contexts and in-memory options for unit test isolation. The on-disk container uses a CloudKit private-database configuration (`iCloud.com.volcrypt.OuterView`) with fail-closed local fallback (see §4.8); the in-memory configuration stays local-only.
- **`BookmarkStore`**: Handles bookmark trees, folder management, deduplication, and favorites flags.
- **`HistoryStore`**: Records visits, refreshes the newest row's title when the page title arrives after the commit snapshot, enforces a 10,000-entry cap, and performs date-range lookups. Init-time `repairCorruptedTitles()` heals legacy search-query titles bound to non-search hosts; `isEquivalentNavigationURL()` tolerates equivalent redirect URLs without cross-path collisions.
- **`TabStore`**: Persists active tabs and session state; P1 adds tab-group CRUD (create/rename with 32-char clamp, delete orphans members to ungrouped, assign). Private tabs are strictly filtered out and never written to disk. `TabRecord.parentTabID` (optional, additive) records link-opened-tab lineage: set only by the two link-open creation paths (`createWebViewWith`, `openInNewTab`), never scrubbed on close; readers resolve parent existence at use time and fail closed (inert) when the parent is gone. `TabSession` carries a CloudKit-safe `tabIdsEncoded` order string dual-written by `writeSnapshot` alongside the legacy `tabIds` array; `loadSession` prefers the encoded value when non-empty (see §4.8).
- **`RecentSearchStore`**: Tracks recent search queries with individual or complete clearance. It is the sole recent-query store — `RecentSearchesView` binds to it via injection; no parallel persistence subsystem exists.
- **`ReadingListStore`**: URL-deduped (earliest wins, empty-title refresh), 2000-entry cap with prune-oldest, read-state flags, ordering, and clearance.
- **`DownloadsManager`**: `@MainActor` row plus progress plus destination owner writing to `Documents/Downloads` (exposed in Files via UIFileSharingEnabled); sanitized names with `name (2).ext` collision handling; row state (inProgress/finished/failed) with cancel/delete plus batched clear; Clear All on both the sheet toolbar and the rail path is gated behind an explicit confirmation prompt (`promptClearAllDownloads`/`.confirmationDialog`) before `deleteAll()` runs; aggregate overallProgress for the address-bar ring; folder export to the Files app. Transfer ownership splits: standard tabs via `BackgroundDownloadService` (background `URLSession`), private tabs via in-process `WKDownload`.
- **`BackgroundDownloadService`**: Singleton background `URLSession` (`com.volcrypt.OuterView.downloads`, non-discretionary, launch events) for standard tabs; wake handling via `DownloadBackgroundDelegate` storing the handler and the session delegate popping it in finish-events exactly once.

### 4.7 Security: Private-Tab Gate & Content Blocking
- **`BiometricAuthService`** (`Sources/Services/Security/BiometricAuthService.swift`): `@MainActor` Face ID / Touch ID / passcode evaluator (`LAContext`, `.deviceOwnerAuthentication`) guarding private tabs behind the `BiometricAuthenticating` protocol for test injection. Private entry is single-gated via `requestPrivateMode(authenticatedApply:)`; backgrounding with any private tab sets `isPrivateSessionLocked`, and scene activation with private content visible requires "Unlock Private Browsing" authentication. Failure, cancellation, or no enrolled biometrics/passcode fails closed to standard mode, and the lock clears so standard browsing never re-prompts. The gate defaults on: `shouldRequireBiometricsForPrivateMode` reads `SettingsViewModel.requireBiometricsDefaultsKey` (`requireBiometricsForPrivateTabs`) with a `?? true` fallback.
- **`ContentBlockerService`**: Native `WKContentRuleList` blocker compiled once through `WKContentRuleListStore` (identifier `OuterViewContentBlockerRules`) from 16 built-in third-party rules covering major ad and tracking networks (DoubleClick, Google Analytics/Tag Manager/Ads, AppNexus, ScoreCardResearch, Quantserve, Criteo, Advertising.com, Taboola, Outbrain, Hotjar, Twitter analytics) plus popups and popunders. Compilation is single-flight (concurrent callers park on the in-flight compile; failures re-check the store before giving up). `TabPool` tracks every `WKUserContentController` and installs the compiled rules on creation with the flag defaulting on (`SettingsViewModel.blockTrackersDefaultsKey`, `blockTrackersAndAds`, `?? true`); `applyContentBlockerEnabled` is the single live toggle owner, fanning the flag out to both shared configurations plus every live page with no restart, and toggles serialize through a chain so rapid flips apply in order.

### 4.8 iCloud Sync
- **`OuterViewDatabase`** (`Sources/Services/Persistence/OuterViewDatabase.swift`): Sole owner of container selection in `init(inMemory:)`. The on-disk container uses one `ModelConfiguration` with `cloudKitDatabase: .private` plus container identifier `iCloud.com.volcrypt.OuterView` covering all eight models; the in-memory path stays local-only with `.none`. CloudKit setup failure falls back to a local-only container with identical schema, logging through `os.Logger` plus reporting to the sync monitor. Autosave stays disabled.
- **`SyncedSettingsStore`** (`Sources/Services/Persistence/SyncedSettingsStore.swift`): Sole owner of all `NSUbiquitousKeyValueStore` traffic. Synced keys are exactly `searchEngine`, `requireBiometricsForPrivateTabs`, `blockTrackersAndAds`, `portraitTabBarPosition`, `readerTheme`, `readerFontSize`, `siteZoom`, `websiteSettings`; the `iCloudSyncEnabled` toggle stays local-only. Every local write to a synced key also writes KVS; remote-change notification pulls KVS values into local defaults plus stamps the last-sync date. Toggle changes apply on next launch.
- **`CloudSyncMonitor`** (`Sources/Services/Persistence/CloudSyncMonitor.swift`): Sole owner of sync status truth (`waitingForSignIn`, `syncing`, `synced`, `failed` with a 200-char message clamp). Reads `CKContainer` account status plus observes `NSPersistentCloudKitContainer` events plus KVS change notifications. `SettingsViewModel` reads this monitor plus never queries `CKContainer` directly.
- **Tab order encoding**: `TabSession.tabIdsEncoded` (comma-joined uuidStrings) dual-written by `TabStore.writeSnapshot` alongside the legacy `tabIds` array; `TabStore.loadSession` prefers the encoded value when non-empty. Strip order plus selection merge last-writer-wins across devices; per-device tab listings stay deferred.
- **Private-host ephemerality**: `WebsiteSettingsStore` holds private-host values in session memory only (128-host FIFO cap) behind a required `isPrivate` flag on every public method; private hosts never reach `UserDefaults`, KVS, plus CloudKit. Clearing history plus clearing tabs deletes synced rows on all devices through CloudKit tombstones.
- **Packaging requirement**: `Support/Info.plist` declares `UIBackgroundModes` with `remote-notification`; without it CloudKit silent pushes never wake the app and the console reports the missing mode. No extra entitlement is declared for this; automatic signing provisions the push environment.
- **Settings UI**: `SettingsView` renders a top `iCloud Sync` section (toggle, status row, last-synced caption, scope footer, signed-out guidance text with zero alerts); `SettingsViewModel` owns toggle persistence plus status-text mapping.

## 5. Key Contracts & Interaction Flows

### 5.1 Chrome Scroll State Machine
```
[Finger Down]      ──> Resets gesture accumulators only; visible chrome stays

[User Down-Scroll] ──> Accumulate Delta ≥ 8 pt  ──> Rail Collapses (no button)
                    ──> Accumulate Delta ≥ 24 pt ──> Address Pill Minifies (30 pt)

[User Up-Scroll]   ──> Accumulate Delta ≥ 32 pt ──> Rail Expands; Address Pill Restores (44 pt)

[Pill Tap Hidden]  ──> Immediate Override       ──> Rail Expands plus Pill Expands
```
On regular width landscape, toolbar plus strip visibility is bound to `state.pill == .minified`: both collapse in the same 24 pt step the pill minifies (never the 8 pt rail step) and restore with it; the expanded header reserves layout through top content insets while the collapsed state keeps a translucent remnant with content behind it and an inset-based sticky limit parking page headers below the remnant. Mode 3 keeps the bottom pill and keeps `topBarView` hidden in browsing with `topContentInset = max(0, safeAreaTop)` parking web content below the status cluster (`isHidden == true` in both expanded and minified steps); the transparent `TopBarView` (`showsBackgroundBar == false`) appears only for Settings, Downloads, and BookmarkEditor, while Library and Overview keep `topBarView` hidden (Library with the regular grouped header, Overview with the 44 pt `inlineBar`). Mode 4 (`duoInnerOrPadPortrait`) drops the top bar and horizontal tab strip, running bottom-anchored controls and a vertical tab bar that minifies alongside the bottom pill. Thresholds are shared across placements. Status bar: modes 1, 2, and 4 hide the system status bar while the pill is minified; mode 3 always keeps it visible. Submitting an address from the editor keeps the pill expanded in all four modes (matching Safari: large address bar until downward scroll). Scrolling top boundary uses `min(adjustedTop, chromeTop)` so rubber-band settle toward resting top never registers as downward reading scroll. In Mode 2, `TabStripView` supports long-press drag-to-reorder tabs horizontally with persistence shared with the overview collection.

### 5.2 Address Editing & Start Page Coordination
1. **Initiation**: Tapping the address bar invokes `beginEditing()` only when the rail is visible and the pill is expanded:
   - On `.compact`, tabs with an active web page display the unified `StartPageView` underneath `editorView` docked above `keyboardLayoutGuide`, and `SideRailView` transitions to `RailMode.startPage` presenting the Blue Checkmark (`Done`).
   - On `.regular`, the active web page and `TopBarView` browsing buttons (`<`, `📖`, `+`, `⧉`) remain untouched while `AddressEditorView` floats above `TopBarView` as a centered blurred popover card showing the active URL + embedded Favorites grid.
2. **Typing**: Keystrokes switch `AddressEditorView` into typing mode:
   - Synchronous local suggestions render instantly (over `.systemBackground` on `.compact`, or inside the blurred popover card on `.regular`).
   - Debounced remote suggestions merge seamlessly upon arrival.
3. **Exit**: Tapping the Blue Checkmark in the side rail on `.compact`, or tapping outside the popover card / pressing Escape on `.regular`, invokes `dismissStartPageOrEditing()`, dismissing the keyboard and hiding the editor.
4. **Mode 3 library editing**: Tapping the pill opens `bookmarksLibraryView` at `.startPage` with the bottom chrome retained (bottom leading stack hidden, pill expanded to the leading edge, bottom trailing always `xmark` "Dismiss"). Tapping the address bar shows `RecentSearchesView` over the Start Page content and flips `LibraryTabBar` segment 0 to the magnifier; switching to another tab restores the grid icon, and tapping segment 0 returns to the Start Page. Library tab switches run the full editing teardown (no split FSM/first-responder state). Exiting via the bottom `xmark` "Dismiss" (`dismissStartPageOrEditing`) leaves editing and closes the library back to the web page; selecting any suggestion, bookmark, history, or reading-list row — or pressing Return — closes the library and loads immediately.

### 5.3 Page Menu Structure
The page menu accessed from the address capsule is built by `BrowserRootViewController.makePageMenu(model:)` (`Sources/Browser/RootView/BrowserRootViewController+PageMenu.swift`) from `PageMenuModel` (`Sources/Browser/Chrome/PageMenuModel.swift`) in strict top-to-bottom order below the palette: App, Tools, Save. There is no `Open Start Page` row.
- **Top Inline Palette Row** (`[.displayInline, .displayAsPalette]`): Back (`canGoBack`), Forward (`canGoForward`), Reload (`canReload`), Share (`canShare`).
- **App section** (`displayInline`): `Website Settings…` (disabled unless `canEditWebsiteSettings`), then `Settings…` (always enabled).
- **Tools section** (`displayInline`): `Downloads` (`canOpenDownloads`), desktop toggle (`Request Desktop Website` / `Request Mobile Website` flipping with `isDesktopMode`, disabled unless `canToggleDesktopMode`), `Text Zoom` submenu (`Zoom In` / `Zoom Out` / `Reset`, each disabled unless `canFind`), `Find on Page` (disabled unless `canFind`).
- **Save section** (`displayInline`): conditional Reader row (`Show Reader` / `Hide Reader` flipping with `isReaderActive`, present only when `showsReaderItem` is true, disabled unless `canFind`), `Add to Reading List` / `Remove from Reading List` (flipping with `isInReadingList`, disabled unless `canAddToReadingList`), `Save` submenu (`Add Bookmark`, then `Add to Favorites` / `Remove from Favorites` flipping with `isFavorite`; both disabled unless `canSave`), `Print and PDF` submenu (`Print`, then `Save as PDF`; both disabled unless `canPrint`).
- **Fail-closed gates**: `PageMenuModel.init` derives `canReload` / `canShare` / `canSave` / `canFind` from `URLNormalizer.isLoadable(url)`; `canToggleDesktopMode`, `canPrint`, and `canEditWebsiteSettings` are each `flag && hasLoadableURL`, so every gated row renders disabled without a loadable page.

### 5.4 Find in Page Flow
1. Page menu "Find on Page" → `beginFind()`: the find capsule swaps into the expanded pill's frame (full content width); pill suppressed while active.
2. Typing runs `window.__outerviewFind(query)` → live highlights + "n/m" counter; prev/next cycle via `findStep(±1)`.
3. Done → `endFind()`: `clearFind()` + pill restored in the FSM's current state (rail commands keep animating during find).

### 5.5 Tab Overview Chrome Flow
1. **Rail**: Search + ellipsis menu (Manage Tab Groups, New Group…, Close All Tabs with confirm sheet) on top; New Tab and Done at the bottom, all rendered as system toolbar glass via `SystemToolbarMapper` with tap plus hold elasticity.
2. **Tabs pill**: One bottom glass capsule (`TabGroupPickerBar`); tap opens `TabGroupsSheetController` (medium detent, grabber); tapping an inactive segment instead slides the pill over and applies that selection; a horizontal scrub slides the pill between segments with selection haptics, applies each hovered selection live via single-refresh `applySelectionBatched`, and commits on release (cancel restores the pre-scrub selection).
3. **Sheet pill + rows**: A `pillControl: UISegmentedControl` under the header mirrors `LibraryTabBar` (segments derived via `Segment(row:)`); tapping a pill segment or a table row selects All/Private/a group and dismisses; create rows prompt for a name and forward the batch `didCreateGroup:withTabIDs:` delegate call; long-press (context menu) on a group row offers Rename/Delete, which keep the sheet open (owner-refresh re-reads `stateProvider`).

### 5.6 Interactive Pill Pan Flows
1. **Gesture ownership**: `AddressBarView` owns one axis-locking pan (tap requires it to fail). The axis with the larger |translation| locks once either axis exceeds 8pt; only the locked axis emits `PillPanEvent` began/changed/ended on `onHorizontalPan` or `onVerticalPan`. Commit math is pure: horizontal commits at 0.40 of content width or on a same-direction 800 pt/s fling, vertical at 0.30 of view height or on an upward 800 pt/s flick. No haptic on any pill path.
2. **Horizontal drag**: `handleHorizontalPan` scopes to `visibleTabs` in `tabs` order; left means next, right means previous; right-at-first clamps with elastic bounce even on a matching fling; left-past-last commits one same-scope Start Page tab inheriting private flag plus group. The outgoing content is snapshotted on began and follows the finger while the incoming tab renders live underneath; release settles with the shared settle curve (commit finishes, cancel restores identity plus origin selection). Ignored while editing, Find active, or overview visible.
3. **Vertical drag**: `handleVerticalPan` shrinks the live `contentContainer` in place into a card (scale 1 minus 0.30 times progress, 1:1 finger tracking anchoring the touch point via `overviewDragAnchorY`/`centerY`, 24 times progress corner radius) while the prepared overview fades in proportionally; the page never slides off-screen during the drag and pill plus rail stay fixed. Release at or past 0.30 — or on an upward 800 pt/s flick — commits into `selectedCardFrame`; a slower short drag pops back with selection unchanged; downward drags are no-ops. Ignored while editing, Find active, or overview visible.

### 5.7 Edge Navigation Flows
Left edge: when the tab has back history, WebKit's native gesture (`allowsBackForwardNavigationGestures`, enabled only in `WebPageController.init`) runs the Safari-exact interactive page-slide back. When there is no history but the tab is a link child (`TabRecord.parentTabID` resolves to an existing tab), `BrowserRootViewController+EdgeSwipe.swift` owns the interactive close: the child page slides right following the finger while the parent tab slides in from the left underneath, commit at 0.40 of width or on an 800 pt/s same-direction flick (`AddressBarView.shouldCommitHorizontal` direction `.right`), cancel restores the child selection, and commit closes through `closeTab` with the parent pre-selected. The gate is fail-closed — browsing state (`!isEditingAddress`, `!isFindActive`, `!isOverviewVisible`), no active pill pan or edge session, no start-page state, `errorContainer` hidden, parent exists — and is re-evaluated at touch time in `gestureRecognizerShouldBegin`. Right edge: WebKit-native forward. No haptic on any edge path.

### 5.8 iCloud Sync & Status Flow
1. **First launch with iCloud**: `OuterViewDatabase` opens the CloudKit private container; existing local rows upload; `SyncedSettingsStore.startSync` backfills empty KVS keys from local defaults.
2. **Second device / reinstall**: library rows plus tab records download; `TabStore.loadSession` prefers `tabIdsEncoded` when non-empty with legacy fallback; strip order converges last-writer-wins on the union of records.
3. **Settings change**: a synced-key write mirrors to KVS immediately; the KVS change notification pulls remote values into local defaults on other devices.
4. **Status surfacing**: `CloudSyncMonitor` maps account plus event state to waitingForSignIn / syncing / synced / failed; `SettingsViewModel` renders the text; a stale failure clears on the next successful import.
5. **Privacy gate**: private tabs never reach any store; private per-host settings stay in session memory only; per-site text zoom for private tabs applies to the live view only; clearing history plus clearing tabs deletes synced rows everywhere through CloudKit tombstones.

## 6. Engineering Standards & Test Automation Contracts

### Test & Target Matrix
- **Target Device**: OuterView specifically targets the **iPhone Duo** running iOS 27.1+ (outer portrait display 466 × 678 pt). Automated builds and unit tests target the iOS Simulator running iOS 27.1+:
  ```bash
  xcodebuild test -scheme OuterView -destination "platform=iOS Simulator,name=iPhone 17 Pro" -only-testing:OuterViewTests
  ```
- **Test Scope & Architecture**: Tests span two bundles: `OuterViewTests` (`bundle.unit-test`) for in-process logic and layout, plus `OuterViewUITests` (`bundle.ui-testing`, `TEST_TARGET_NAME: OuterView`) for out-of-process store screenshot capture via the Fastlane snapshot pipeline.
  - **Unit Tests (`Tests/Unit/`)**: Pure business logic, parsers, algorithms, view models, and state controllers.
  - **View Integration Tests (`Tests/Views/`)**: In-process UIKit hierarchy and layout verification anchored to `TestWindow.swift`. Out-of-process `XCUIApplication` coverage lives only in `OuterViewUITests`, never duplicated here.
  - **Screenshot UI Tests (`OuterViewUITests/`)**: Out-of-process `XCUIApplication` capture (`OuterViewScreenshots`) asserting `BrowserRootViewController.placement` behavior (compact vs regular) and producing store screenshots through the `Snapfile`/`Fastfile` snapshot pipeline on locked simulators.
  - **Test Plans**: Managed via `Support/TestPlans/OuterView.xctestplan` (default, all tests: `OuterViewTests` plus `OuterViewUITests`, randomized ordering) and `Support/TestPlans/OuterViewFast.xctestplan` (fast logic/model unit tests only: `OuterViewTests` with slow view suites skipped, `OuterViewUITests` excluded by design).
  - **No Parallel Testing Policy**: Parallel testing MUST remain disabled in both test plans with `"parallelizable": false` on every test target; execution ordering stays randomized with sequential simulator execution.
- **Project Maintenance**: Whenever files are added, removed, or project configuration changes, `xcodegen generate` must be run to synchronize `OuterView.xcodeproj` from `project.yml`.

### Architectural Invariants
- **Sequential Simulator Execution (No Parallel Test Clones)**: Parallel testing on iOS Simulator targets is strictly forbidden; simulators execute sequentially with no parallel test clones to keep unit and screenshot runs deterministic.
- **No Hardcoded Screen Dimensions**: All view layouts must use dynamic safe-area insets, layout guides, and trait collections. Never query `UIScreen.main` or branch on device models. Mode-classification carve-out: interface-mode resolution may read documented outer-display geometry (466 pt bounds, right safe area ≥ 44) and simulator name/launch arguments to select the mode; those values never enter layout math.
- **No Private APIs**: Safari functionality (bookmarks import, icon rendering, suggestions, find, reader, downloads) is achieved strictly through public iOS SDKs.
- **Memory Safety & Process Isolation**: Inactive web views must be evicted via `TabPool` to prevent WebContent process bloat on memory-constrained devices.
- **Single-Owner Menus**: The page menu structure is edited only where the integration task specifies; feature tasks expose capability APIs and never fork the menu builder.
- **Single-Owner Tuck + Chrome Composition**: Library-list tuck decisions live only in `LibrarySearchTuckController`; library select-mode rail composition lives only in `BrowserRootViewController.updateLibraryRailItems(for:)`; tab-card dismissal lives only in `TabCardCell`; bottom overview chrome lives only in the TabOverview trio — `TabGroupPickerBar` (segment capsule/sliding pill/scrub gestures), `TabOverviewViewController+Picker.swift` (selection/menu/sheet application), and `TabOverviewViewController` (hosts and constrains `pickerBar`). Call sites delegate; they never re-implement.
- **Single-Owner Pill Gestures + Tab Scope + Downloads**: Pill recognizers plus commit plus card math live only in `AddressBarView`; interactive horizontal switching lives only in `handleHorizontalPan` plus `pillTargetIndex`; interactive overview drag lives only in `handleVerticalPan`; swipe scope plus overflow creation live only in `handleHorizontalPan` plus `commitHorizontalOverflow` plus `makeOverflowTabInCurrentScope`; standard transfers live only in `BackgroundDownloadService`; rows plus destinations live only in `DownloadsManager`. Call sites delegate; they never re-implement.
- **Single-Owner Interface Mode + Status Bar**: `BrowserInterfaceMode` resolution lives only in `BrowserRootViewController.interfaceMode`; status-bar hiding policy lives only in `BrowserRootViewController.shouldHideStatusBar(for:mode:)`. Call sites delegate; they never re-implement.
- **Single-Owner Toolbar Glass + Chrome Composition**: `RailAction` to system-chrome mapping lives only in `SystemToolbarMapper` (`makeToolbarItems(prefix:suffix:)` plus `makeItem(for:)` plus `toolbar(items:)` plus `populateStack(_:with:axis:)` plus `populateBottomStack`); `SideRailView.setItems(prefix:suffix:)` plus `TopBarView.setItems(prefix:suffix:)` plus `BrowserRootViewController.setChromeItems(prefix:suffix:)` delegate with identical prefix plus suffix arrays so rail plus top plus bottom hosts never diverge. Live reload resets items with zero restart; stale views clear by full remove plus rebuild.
- **Single-Owner Edge Gestures + Tab Parentage**: WebKit's `allowsBackForwardNavigationGestures` is set only in `WebPageController.init` and never toggled at runtime; the left-edge child-tab-close recognizer, `EdgeClosePolicy`, and `EdgeCloseSession` live only in `BrowserRootViewController+EdgeSwipe.swift`, and its commit thresholds are `AddressBarView`'s pure math, never re-implemented; `TabRecord.parentTabID` is written only by the two link-open creation sites (`createWebViewWith`, `openInNewTab`) and never scrubbed on close. Call sites delegate; they never re-implement.
- **Single-Owner iCloud Sync**: `NSUbiquitousKeyValueStore` traffic lives only in `SyncedSettingsStore`; sync status truth lives only in `CloudSyncMonitor`. Stores delegate for their keys; `SettingsViewModel` reads the monitor and never queries `CKContainer` directly. Call sites delegate; they never re-implement.
- **Private-Host Ephemerality**: private-tab hosts never persist. Per-host website settings for private tabs live in `WebsiteSettingsStore` session memory only (128-host FIFO cap); per-site text zoom for private tabs applies to the live view only. Clearing history plus clearing tabs deletes synced rows on all devices through CloudKit tombstones.
- **Single-Path Menu Presentation**: the page-menu button owns one presentation path per tap. With a provider set the system UIMenu owns the tap and the touchUpInside forwarder is uninstalled; without a provider the forwarder presents the fallback sheet. Two simultaneous presentations on one layer log bounds/position decomposition warnings.

## Code Commenting Guidelines

- **File Headers**: Every source and test file must begin with a concise 1-2 line header identifying the subsystem and core responsibility: `// <Subsystem> — <Purpose and role>.`
- **Max 3 Lines**: Comments (headers, doc comments, and inline comments) must be at most 3 lines long.
- **Intent Over Mechanics**: Comments must explain non-obvious rationale, invariants, or edge cases rather than restating mechanics.
- **No Planning-Artifact References**: Code comments must never reference task IDs, session IDs, PR numbers, plan identifiers, or other transient planning artifacts.
